Memoria Machinae — Bugfix #9: Cross-Encoder in the Dream-Replay Loop

Fix for the final issue of Memoria_Machinae_V1_3:

#9 — Dream-phase replay calls full recall(), including cross-encoder reranking, per replay step. The original dream phase called recall_engine.recall(node.embedding, k=5) with no override. Whenever use_cross_encoder is enabled in config — the recommended setting on Jetson-class hardware per the deployment guidance — every one of up to dream_replay_steps (default 20) replay queries in a single consolidation pass ran a full cross-encoder rerank over its candidate set. There was no way to disable this for internal replay queries specifically without also disabling it for real, user-facing recalls, and the documented "~100ms per consolidation pass on Jetson" budget becomes unrealistic once 20 sequential cross-encoder calls are in that loop.

Design of the fix

memory/recall.py (newly reconstructed) defines RecallEngine.recall() with an explicit rerank: bool = True parameter:

Default unchanged for external callers. rerank defaults to True, so any existing real, user-facing recall call gets exactly the same behavior as before — cross-encoder reranking still applies whenever use_cross_encoder is configured and a reranker is wired in.

Internal callers can opt out explicitly. memory/dream.py's DreamPhase.run() now calls recall_engine.recall(node.embedding, k=5, rerank=False) — dream replay is an internal consolidation signal used only to decide whether a node is still "findable" well enough to reinforce, not a user-facing search, so it doesn't need cross-encoder precision.

The cross-encoder itself is represented by CrossEncoderReranker, a lightweight stand-in that tracks how many times it was invoked (so tests can assert directly on call counts) and can simulate extra per-call latency, without needing an actual ML model dependency to validate the fix.

What's included

This file includes the complete, cumulative fixed codebase across all fixes from the original review (#3, #1, #2, #4, #5, #8, and now #9): config.py, metrics.py, memory/graph.py, memory/stack.py, memory/recall.py (new), memory/dream.py (new), schema/common.py, schema/precondition.py, schema/inducer.py, service/auth.py, and their seven test files.

""" memory/graph.py Core memory graph structure. This file contains the fix for bug #3: Before the fix, merge_nodes() only checked *whether* an edge already existed between two nodes before re-pointing it at the merge target: if not self._graph.has_edge(pred, primary_id): self._graph.add_edge(pred, primary_id, **edge_data) Because the underlying store is a simple DiGraph (one edge per node pair, not a MultiDiGraph), if `primary` already had *any* edge from `pred` — e.g. a low-priority `cooccurrence` edge — then a `causal` edge coming from `secondary` was silently discarded on merge. Since precondition learning and the dream phase both walk causal edges, this quietly corrupted exactly the structures those features depend on, with no error or log line to indicate it happened. The fix adds edge-type-aware merge semantics: a `causal` edge is never dropped in favour of a weaker edge type. If no conflict exists, behaviour is unchanged. If both sides are the same edge type, the stronger weight wins instead of arbitrarily keeping whichever was encountered first. """ from __future__ import annotations import time from dataclasses import dataclass, field from typing import Optional import networkx as nx from ..config import CONFIG from ..metrics import MERGE_EDGE_DROPPED_COUNT, MERGE_EDGE_UPGRADED_COUNT # Edges are prioritised when two edge types compete for the same # (u, v) slot in the DiGraph during a merge. Higher number wins. _EDGE_TYPE_PRIORITY = { "cooccurrence": 0, "schema_of": 1, "causal": 2, } @dataclass class EpisodicNode: node_id: str text: str embedding: object = None memory_type: str = "episodic" strength: float = 1.0 created_at: float = field(default_factory=time.time) last_accessed_at: float = field(default_factory=time.time) embedding_meaningful: bool = True class MemoryGraph: """Directed graph of memories connected by cooccurrence, causal, and schema-membership edges.""" def __init__(self, config: Optional[dict] = None): self._config = config or CONFIG self._graph = nx.DiGraph() self._id_to_node: dict[str, EpisodicNode] = {} # ------------------------------------------------------------------ # Basic node/edge operations # ------------------------------------------------------------------ def add_memory(self, node: EpisodicNode) -> None: self._id_to_node[node.node_id] = node self._graph.add_node(node.node_id) def get_node(self, node_id: str) -> Optional[EpisodicNode]: return self._id_to_node.get(node_id) def all_nodes(self) -> list[EpisodicNode]: return list(self._id_to_node.values()) def has_node(self, node_id: str) -> bool: return node_id in self._id_to_node def add_edge(self, u: str, v: str, edge_type: str, weight: float = 1.0) -> None: self._graph.add_edge(u, v, edge_type=edge_type, weight=weight) def add_causal_edge(self, action_id: str, outcome_id: str, weight: float = 1.0) -> None: self._graph.add_edge(action_id, outcome_id, weight=weight, edge_type="causal") def add_cooccurrence_edge(self, a_id: str, b_id: str, weight: float = 1.0) -> None: self._graph.add_edge(a_id, b_id, weight=weight, edge_type="cooccurrence") def predecessors(self, node_id: str) -> list[str]: if node_id not in self._graph: return [] return list(self._graph.predecessors(node_id)) def successors(self, node_id: str) -> list[str]: if node_id not in self._graph: return [] return list(self._graph.successors(node_id)) def get_edge_data(self, u: str, v: str) -> Optional[dict]: if not self._graph.has_edge(u, v): return None return dict(self._graph[u][v]) def remove_node(self, node_id: str) -> None: if node_id in self._graph: self._graph.remove_node(node_id) self._id_to_node.pop(node_id, None) # ------------------------------------------------------------------ # Merge # ------------------------------------------------------------------ def _merge_edge(self, u: str, v: str, edge_data: dict) -> None: """Add an edge from u to v, or upgrade the existing one, without ever silently discarding a higher-priority edge type (e.g. a `causal` edge losing to a pre-existing `cooccurrence` edge). """ if not self._graph.has_edge(u, v): self._graph.add_edge(u, v, **edge_data) return existing = self._graph[u][v] incoming_type = edge_data.get("edge_type") existing_type = existing.get("edge_type") incoming_priority = _EDGE_TYPE_PRIORITY.get(incoming_type, -1) existing_priority = _EDGE_TYPE_PRIORITY.get(existing_type, -1) if incoming_priority > existing_priority: # e.g. incoming causal edge beats an existing cooccurrence edge. self._graph.add_edge(u, v, **edge_data) MERGE_EDGE_UPGRADED_COUNT.inc() elif incoming_priority == existing_priority: # Same edge type on both sides: keep the stronger weight # rather than arbitrarily keeping whichever was seen first. existing["weight"] = max(existing.get("weight", 0.0), edge_data.get("weight", 0.0)) else: # Existing edge already outranks the incoming one; nothing # is added, but this is now an explicit, counted decision # rather than a silent drop. MERGE_EDGE_DROPPED_COUNT.inc() def merge_nodes(self, primary_id: str, secondary_id: str) -> None: """Merge `secondary` into `primary`: re-point secondary's edges at primary (without downgrading any of primary's existing edges), combine strength, and remove secondary from the graph. """ if primary_id == secondary_id: return primary = self.get_node(primary_id) secondary = self.get_node(secondary_id) if primary is None or secondary is None: return # Re-point incoming edges (predecessors -> secondary) at primary. for pred in list(self._graph.predecessors(secondary_id)): if pred == primary_id: continue edge_data = dict(self._graph[pred][secondary_id]) self._merge_edge(pred, primary_id, edge_data) # Re-point outgoing edges (secondary -> successors) at primary. for succ in list(self._graph.successors(secondary_id)): if succ == primary_id: continue edge_data = dict(self._graph[secondary_id][succ]) self._merge_edge(primary_id, succ, edge_data) primary.strength = max(primary.strength, secondary.strength) self.remove_node(secondary_id) # ------------------------------------------------------------------ # Decay / pruning # ------------------------------------------------------------------ def decay_all(self) -> None: decay_rates = self._config["memory_type_decay_rates"] floor = self._config["min_strength_floor"] for node in self._id_to_node.values(): rate = decay_rates.get(node.memory_type, self._config["long_term_decay_rate"]) node.strength = max(floor, node.strength - rate) def prune_eligible(self, node: EpisodicNode) -> bool: eligible = self._config["memory_type_consolidation_eligible"] return eligible.get(node.memory_type, True) 

memoria_machinae/memory/stack.py

""" memory/stack.py The consolidation pass: periodically scans active memories and merges near-duplicate nodes into each other based on cosine similarity between their embeddings. Contains the fixes for bug #4 and bug #8. Bug #4 (zero-embedding NaN) — see the note on cosine_similarity() below; unchanged from the previous fix. Bug #8 — O(n^2) pairwise similarity comparison at scale. The original merge-dedup pass compared every "active" node against every other active node with a plain nested Python loop: for i, node_a in enumerate(active): for node_b in active[i + 1:]: sim = cosine_similarity(node_a.embedding, node_b.embedding) ... This is O(n^2) similarity computations per consolidation pass. The hardware/scale guidance for this system anticipates millions of memories; even at a modest 10,000 active nodes that's ~50 million pairwise comparisons *every consolidation cycle*, almost all of which are wasted work comparing embeddings that are nowhere near each other in vector space. The system already has FAISS-backed ANN infrastructure elsewhere (VectorStore) for exactly this kind of problem; the merge-dedup pass wasn't using it. The fix replaces the brute-force double loop with a KD-tree (scipy.spatial.cKDTree) built once per consolidation pass over L2-normalized embeddings. For unit vectors, Euclidean distance is a monotonic function of cosine similarity (||a - b||^2 = 2 - 2*cos_sim), so a cosine similarity threshold converts *exactly* — not approximately — into a Euclidean search radius. This means the tree-based approach finds precisely the same candidate pairs a brute-force scan would, in average O(n log n) instead of O(n^2), and each candidate is still verified with the exact cosine_similarity() function before merging (belt-and-braces against any floating-point edge case at the radius boundary). If your deployment already has a FAISS-backed VectorStore, swapping the cKDTree here for a call into that store is a drop-in replacement of _find_merge_pairs(); the important part is that dedup is no longer literally quadratic in the number of active nodes. """ from __future__ import annotations import math import numpy as np from scipy.spatial import cKDTree from ..config import CONFIG from ..memory.graph import EpisodicNode, MemoryGraph from ..metrics import CONSOLIDATION_MERGE_COUNT, CONSOLIDATION_SKIPPED_NONMEANINGFUL_COUNT # Matches the epsilon used elsewhere in the codebase (e.g. salience.py) # for normalizing embeddings that may be zero or near-zero. _COSINE_EPSILON = 1e-8 def _normalize_embedding(embedding) -> np.ndarray: """L2-normalize an embedding, safe against zero or near-zero vectors. Shared by cosine_similarity() and the KD-tree candidate search below so the two can never define "normalized" differently and drift apart the way similarly-duplicated parsing logic did in earlier bugs (#1 / #2) in this codebase. """ emb = np.asarray(embedding, dtype=float) return emb / (np.sqrt(emb @ emb) + _COSINE_EPSILON) def cosine_similarity(emb_a: np.ndarray, emb_b: np.ndarray) -> float: """Cosine similarity between two embeddings, safe against zero or near-zero vectors (bug #4 fix). Never raises, never returns nan/inf: a zero vector normalizes to the zero vector, which has similarity 0.0 against anything (including another zero vector). """ return float(_normalize_embedding(emb_a) @ _normalize_embedding(emb_b)) def _cosine_threshold_to_euclidean_radius(threshold: float) -> float: """Convert a cosine similarity threshold into the Euclidean search radius that finds exactly the same pairs, for L2-normalized (unit) vectors: ||a - b||^2 = ||a||^2 + ||b||^2 - 2*a.b = 2 - 2*cos_sim. So cos_sim >= threshold <=> ||a - b|| <= sqrt(2 - 2*threshold). """ threshold = min(1.0, max(-1.0, threshold)) return math.sqrt(max(0.0, 2.0 * (1.0 - threshold))) def _find_merge_pairs(nodes: list[EpisodicNode], threshold: float) -> list[tuple[int, int]]: """Return (i, j) index pairs (i < j, ascending order — matching the order a brute-force nested loop would produce) whose embeddings have cosine similarity >= threshold, without ever comparing every node against every other node. """ if len(nodes) < 2: return [] normalized = np.stack([_normalize_embedding(n.embedding) for n in nodes]) tree = cKDTree(normalized) radius = _cosine_threshold_to_euclidean_radius(threshold) pairs: list[tuple[int, int]] = [] for i in range(len(nodes)): neighbor_indices = sorted(tree.query_ball_point(normalized[i], r=radius)) for j in neighbor_indices: if j <= i: continue # Exact verification guards against any tiny floating-point # discrepancy between the Euclidean-radius approximation # and the true cosine threshold at the boundary. sim = cosine_similarity(nodes[i].embedding, nodes[j].embedding) if sim >= threshold: pairs.append((i, j)) return pairs class MemoryStack: """Owns the consolidation pass over a MemoryGraph: near-duplicate detection and merging of active memory nodes.""" def __init__(self, graph: MemoryGraph, config: dict | None = None): self.graph = graph self._config = config or CONFIG self._threshold = self._config["dedup_similarity_threshold"] def consolidate(self) -> int: """Scan active nodes (those with a meaningful embedding) and merge any pair whose cosine similarity meets the configured threshold, using KD-tree candidate search instead of an O(n^2) brute-force scan (bug #8 fix). Returns the number of merges performed. """ considered: list[EpisodicNode] = [] for node in self.graph.all_nodes(): if node.embedding is None: continue if not node.embedding_meaningful: CONSOLIDATION_SKIPPED_NONMEANINGFUL_COUNT.inc() continue considered.append(node) merge_count = 0 if len(considered) < 2: return merge_count merged_ids: set[str] = set() for i, j in _find_merge_pairs(considered, self._threshold): node_a, node_b = considered[i], considered[j] if node_a.node_id in merged_ids or node_b.node_id in merged_ids: continue self.graph.merge_nodes(node_a.node_id, node_b.node_id) merged_ids.add(node_b.node_id) merge_count += 1 CONSOLIDATION_MERGE_COUNT.inc() return merge_count 

memoria_machinae/memory/recall.py

""" memory/recall.py Vector-similarity recall over the memory graph, with optional cross-encoder reranking of the top candidates. This module defines the `rerank` parameter that the bug #9 fix (memory/dream.py) depends on to let internal, consolidation-only queries skip the expensive reranking step while leaving real user-facing recalls unaffected. """ from __future__ import annotations from dataclasses import dataclass from typing import Optional, Protocol from ..config import CONFIG from ..memory.graph import EpisodicNode, MemoryGraph from ..memory.stack import cosine_similarity from ..metrics import CROSS_ENCODER_RERANK_COUNT class Reranker(Protocol): def rerank(self, query_embedding, candidates: list[EpisodicNode]) -> list[EpisodicNode]: ... @dataclass class CrossEncoderReranker: """Stand-in for a real cross-encoder reranker. In production this loads a cross-encoder model and calls `.predict()` per candidate, which is inherently much more expensive per call than a plain vector-similarity sort — that expense is exactly why bug #9 matters. This stand-in tracks how many times it was invoked (so tests can assert on it directly) and can simulate extra per-call latency, without pulling in an actual ML model dependency. """ extra_latency_seconds: float = 0.0 call_count: int = 0 def rerank(self, query_embedding, candidates: list[EpisodicNode]) -> list[EpisodicNode]: self.call_count += 1 if self.extra_latency_seconds: import time time.sleep(self.extra_latency_seconds) CROSS_ENCODER_RERANK_COUNT.inc() # Real behavior is a re-sort by exact cosine similarity — a real # cross-encoder would use a richer joint query/candidate signal, # but for this fix what matters is *whether* it's invoked, not # the quality of its ranking. return sorted(candidates, key=lambda n: -cosine_similarity(query_embedding, n.embedding)) class RecallEngine: """Ranks memory nodes by similarity to a query embedding, with an optional cross-encoder rerank pass over the top candidates. """ def __init__( self, graph: MemoryGraph, config: Optional[dict] = None, reranker: Optional[Reranker] = None, ): self.graph = graph self._config = config or CONFIG self._reranker = reranker def recall(self, query_embedding, k: int = 10, rerank: bool = True) -> list[EpisodicNode]: """Return up to `k` nodes ranked by similarity to `query_embedding`. `rerank` defaults to True, preserving existing behavior for real, user-facing recall calls: if `use_cross_encoder` is enabled in config and a reranker is configured, the top candidates get a cross-encoder rerank pass. Internal callers that don't need that precision — like the dream phase's consolidation-only replay queries — can pass `rerank=False` to skip it entirely, regardless of the global config setting. """ candidates = [ n for n in self.graph.all_nodes() if n.embedding is not None and n.embedding_meaningful ] if not candidates: return [] overfetch = k * self._config.get("recall_overfetch_factor", 3) ranked = sorted(candidates, key=lambda n: -cosine_similarity(query_embedding, n.embedding)) top = ranked[:overfetch] should_rerank = rerank and self._config.get("use_cross_encoder", False) and self._reranker is not None if should_rerank: top = self._reranker.rerank(query_embedding, top) return top[:k]

""" memory/dream.py The "dream" consolidation phase: replays a handful of weak-but- causally-connected memories through the recall engine to reinforce them if they're still findable. Contains the fix for bug #9. Before the fix, the dream phase called the recall engine with no override: results = recall_engine.recall(node.embedding, k=5) Whenever `use_cross_encoder` is enabled in config — the recommended setting on Jetson-class hardware per the deployment guidance — this meant every one of up to `dream_replay_steps` (default 20) replay queries during a *single* consolidation pass ran a full cross-encoder rerank over its candidate set. Cross-encoder inference is inherently far more expensive per call than a plain vector-similarity sort, and there was no way to disable it for *internal* replay queries specifically without also disabling it for real, user-facing recalls. The documented "~100ms per consolidation pass on Jetson" budget becomes unrealistic once 20 sequential cross-encoder calls are sitting inside that pass. The fix threads an explicit `rerank: bool` parameter through RecallEngine.recall() (see memory/recall.py) and has the dream phase call it with `rerank=False`. Dream replay is an internal consolidation signal used only to decide whether to reinforce a node's strength — it doesn't need cross-encoder-grade ranking precision, it needs to be cheap enough to run `dream_replay_steps` times per pass. External recall() callers are completely unaffected: `rerank` defaults to True, so real user-facing recall behavior is unchanged by this fix. """ candidates = [ node for node in self.graph.all_nodes() if node.embedding is not None and self._causal_successor_count(node.node_id) >= self._min_causal_successors ] candidates.sort(key=lambda n: n.strength) return candidates[: self._replay_steps] def run(self) -> DreamPhaseResult: weak_nodes = self._select_weak_causal_nodes() reinforced: list[str] = [] for node in weak_nodes: # Bug #9 fix: internal replay queries never pay for # cross-encoder reranking, regardless of the global # use_cross_encoder config setting. Plain vector-similarity # ranking is enough signal to decide whether this node is # still "findable" for consolidation purposes. results = self._recall_engine.recall(node.embedding, k=5, rerank=False) DREAM_REPLAY_COUNT.inc() if any(r.node_id != node.node_id for r in results): node.strength = min(1.0, node.strength + self._reinforcement_amount) reinforced.append(node.node_id) return DreamPhaseResult( replayed_node_ids=[n.node_id for n in weak_nodes], reinforced_node_ids=reinforced, ) 

memoria_machinae/schema/common.py

""" schema/common.py Shared text-parsing helpers for schema and meta-schema nodes, used by both schema/precondition.py and schema/inducer.py. """ from __future__ import annotations def extract_schema_actions(schema_text: str) -> set[str]: """Return the lowercased set of action tokens encoded in a schema or meta-schema node's text, e.g.: "schema:grasp:FAILED | generalised from 3 observations | ..." -> {"grasp"} "schema:grasp->pick:FAILED | generalised from 2 observations" -> {"grasp", "pick"} "meta_schema_L2:grasp | composed_of 2 schemas" -> {"grasp"} Trailing descriptive text (after the first " | ") is always stripped before parsing, so it can never leak into the action token set — this is what makes the parser safe to reuse for meta-schema nodes at any hierarchy level, not just flat level-1 schema nodes. """ schema/precondition.py Learns which entities tend to precede a schema's action along causal edges, i.e. its likely preconditions. Contains the fix for bug #1. Before the fix, the schema's own action entity was excluded from its precondition list with: entity.lower() not in schema_node.text.lower().split(':')[1].split(':')[0] Two separate problems here: 1. `in` on strings is *substring* containment, not equality. It breaks the moment `pattern_key` is a bigram like "grasp->pick:FAILED" (schema text "schema:grasp->pick:FAILED"), because splitting on ':' alone leaves "grasp->pick" un-split, so bigram schemas never correctly identified either action. """ schema/inducer.py Composes flat (level-1) schemas into higher-level meta-schemas by grouping schema/meta-schema nodes that share the same underlying action(s) and rolling groups above a minimum size into a new `meta_schema_L{level}` node. Contains the fix for bug #2. Before the fix, the grouping key used to decide which nodes belong together at a given hierarchy level was extracted with: parts = node.text.split(':') action_token = parts[1].split('->')[0].strip() This works for level-1 schema text ("schema:grasp:FAILED | ...") since parts[1] == "grasp" cleanly. But it breaks the moment `node` is itself a meta-schema node produced by a *previous* composition pass, e.g. "meta_schema_L2:grasp | composed_of 2 schemas". Splitting on ':' there gives parts[1] == "grasp | composed_of 2 schemas" (the entire tail, including the trailing description, because there's no second ':' to stop at), and .split('->')[0] does nothing to help since there's no '->' in that string either. The resulting "action_token" for every level-2+ meta-schema node therefore includes its own unique "composed_of N schemas" suffix, so no two meta-schema nodes ever produce the same grouping key — which means groups above the minimum size never form, and hierarchical composition silently stops working above level 2, no matter how `schema_hierarchy_levels` is configured. The fix reuses the same robust parser as the bug #1 fix (schema/common.py's extract_schema_actions), which strips the trailing " | ..." description *before* parsing the action segment. """ actions = extract_schema_actions(schema_text) if not actions: return None return "+".join(sorted(actions)) @dataclass class CompositionResult: level: int meta_nodes_created: list[str] class SchemaInducer: """Rolls schema and meta-schema nodes up into higher-level meta-schemas across `schema_hierarchy_levels` levels.""" def __init__(self, config: dict | None = None): self._config = config or CONFIG self._min_count = self._config["schema_compose_min_count"] self._max_levels = self._config["schema_hierarchy_levels"] self._node_counter = itertools.count() def _is_prior_level_node(self, text: str, level: int) -> bool: """A node is eligible to be composed *into* level `level` if it's a flat schema (for level 2) or a meta-schema node one level below (for level > 2).""" if level == 2: return is_flat_schema_node(text) return is_level_n_node(text, level - 1) def _already_composed_at_level(self, graph: MemoryGraph, node_id: str, level: int) -> bool: """True if `node_id` already has a schema_of edge into an existing meta_schema_L{level} node, so repeated composition passes don't create duplicate meta-nodes for the same group.""" for succ_id in graph.successors(node_id): succ = graph.get_node(succ_id) if succ is not None and is_level_n_node(succ.text, level): return True return False def _candidates_for_level(self, graph: MemoryGraph, level: int) -> list[EpisodicNode]: candidates = [] for node in graph.all_nodes(): if node.memory_type != "procedural": continue if not self._is_prior_level_node(node.text, level): continue if self._already_composed_at_level(graph, node.node_id, level): continue candidates.append(node) return candidates def _new_node_id(self, level: int) -> str: return f"meta_L{level}_{next(self._node_counter)}" def hierarchical_composition(self, graph: MemoryGraph) -> list[CompositionResult]: """Run composition for every level from 2 up to `schema_hierarchy_levels`, in order, so that a level-3 pass sees the meta-schema nodes a level-2 pass just created within the same call. Notes on scope

memory/recall.py and memory/dream.py are newly reconstructed for this fix, since only the single buggy recall() call site was described in the original review, not the surrounding recall/dream modules. I built a RecallEngine with a real (if simplified) candidate-ranking and optional-rerank pipeline, and a DreamPhase that selects weak causal nodes and replays them, so the fix could be exercised end-to-end rather than as an isolated parameter check. If your actual modules differ structurally, the load-bearing pieces are: (1) recall() accepting an explicit rerank parameter defaulting to True, and (2) the dream phase's replay call passing rerank=False.

CrossEncoderReranker is a stand-in, not a real cross-encoder. It tracks call counts and can simulate latency via time.sleep(), which is sufficient to validate "the dream phase never invokes it" and "invoking it 20 times would be slow" without needing an actual model dependency. In production this class would wrap a real cross-encoder model's .predict() call — the fix itself (the rerank parameter and the dream-phase call site) is independent of what the reranker actually does internally.

Backward compatibility was a deliberate design constraint, not just a side effect: rerank defaulting to True means this fix is a pure addition from the perspective of any existing external caller of recall() — nothing about real, user-facing recall behavior changes.

This closes out every item: #3 (causal-edge merge), #1 (precondition substring bug), #2 (hierarchical composition), #4 (zero-embedding NaN), #5 (auth bypass), #8 (O(n²) dedup), and now #9 (cross-encoder in dream replay).
