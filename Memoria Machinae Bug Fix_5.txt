Memoria Machinae — Bugfix #5: dev_subject Auth Bypass

Fix for the fifth bug identified in  Memoria_Machinae_V1_3 — the only one flagged as an active security issue rather than a data-quality bug:

#5 — 'dev_subject' is a hardcoded, unconditional authorization bypass. The original check was if token_subject != 'dev_subject' and token_subject != subject_id: raise HTTPException(...). Any token minted with the literal subject string 'dev_subject' was granted access to every subject's memories, in every environment — production included. There was no flag, no environment check, nothing gating it. Anyone who could mint, guess, or reuse a leaked dev-fixture JWT with subject 'dev_subject' had standing access to every user's data, regardless of known_agent_ids or any per-subject consent the system otherwise enforces.

Design of the fix

service/auth.py (reconstructed here, since only the buggy if statement was quoted in the original review) implements check_subject_access() with the bypass now gated behind an explicit, off-by-default dev_mode config flag:

Fail closed by default. CONFIG["dev_mode"] defaults to False. A deployment that never explicitly opts in gets the bypass fully disabled — a mismatched token subject is always denied, including one with subject 'dev_subject'. dev_mode missing from a config dict entirely is also treated as disabled, not as an implicit bypass.

The bypass only ever applies to the specific 'dev_subject' sentinel — enabling dev_mode does not grant blanket cross-subject access; a mismatched arbitrary subject is still denied even with dev_mode on.

Visible when used. Every time the bypass actually fires, it now logs a WARNING and increments a dedicated metric (DEV_SUBJECT_BYPASS_USED_COUNT) — so even in a legitimate local-dev environment where dev_mode=True is intentional, its use is never silent, and a stray non-zero value on that metric in any non-dev environment is an unambiguous signal something is misconfigured.

config.validate_config() now requires dev_mode to be explicitly present in config at all (not just falsy-by-omission), so a deployment can't accidentally ship without ever having made the decision one way or the other.

What's included

This file includes the complete, cumulative fixed codebase across all four fixes so far (#3, #1, #2, #4, and now #5): config.py, metrics.py, memory/graph.py, memory/stack.py, schema/common.py, schema/precondition.py, schema/inducer.py, service/auth.py (new), and their five test files.

""" memory/graph.py Core memory graph structure. This file contains the fix for bug #3: Before the fix, merge_nodes() only checked *whether* an edge already existed between two nodes before re-pointing it at the merge target: if not self._graph.has_edge(pred, primary_id): self._graph.add_edge(pred, primary_id, **edge_data) Because the underlying store is a simple DiGraph (one edge per node pair, not a MultiDiGraph), if `primary` already had *any* edge from `pred` — e.g. a low-priority `cooccurrence` edge — then a `causal` edge coming from `secondary` was silently discarded on merge. Since precondition learning and the dream phase both walk causal edges, this quietly corrupted exactly the structures those features depend on, with no error or log line to indicate it happened. The fix adds edge-type-aware merge semantics: a `causal` edge is never dropped in favour of a weaker edge type. If no conflict exists, behaviour is unchanged. If both sides are the same edge type, the stronger weight wins instead of arbitrarily keeping whichever was encountered first. """ from __future__ import annotations import time from dataclasses import dataclass, field from typing import Optional import networkx as nx from ..config import CONFIG from ..metrics import MERGE_EDGE_DROPPED_COUNT, MERGE_EDGE_UPGRADED_COUNT # Edges are prioritised when two edge types compete for the same # (u, v) slot in the DiGraph during a merge. Higher number wins. _EDGE_TYPE_PRIORITY = { "cooccurrence": 0, "schema_of": 1, "causal": 2, } @dataclass class EpisodicNode: node_id: str text: str embedding: object = None memory_type: str = "episodic" strength: float = 1.0 created_at: float = field(default_factory=time.time) last_accessed_at: float = field(default_factory=time.time) embedding_meaningful: bool = True class MemoryGraph: """Directed graph of memories connected by cooccurrence, causal, and schema-membership edges.""" def __init__(self, config: Optional[dict] = None): self._config = config or CONFIG self._graph = nx.DiGraph() self._id_to_node: dict[str, EpisodicNode] = {} # ------------------------------------------------------------------ # Basic node/edge operations # ------------------------------------------------------------------ def add_memory(self, node: EpisodicNode) -> None: self._id_to_node[node.node_id] = node self._graph.add_node(node.node_id) def get_node(self, node_id: str) -> Optional[EpisodicNode]: return self._id_to_node.get(node_id) def all_nodes(self) -> list[EpisodicNode]: return list(self._id_to_node.values()) def has_node(self, node_id: str) -> bool: return node_id in self._id_to_node def add_edge(self, u: str, v: str, edge_type: str, weight: float = 1.0) -> None: self._graph.add_edge(u, v, edge_type=edge_type, weight=weight) def add_causal_edge(self, action_id: str, outcome_id: str, weight: float = 1.0) -> None: self._graph.add_edge(action_id, outcome_id, weight=weight, edge_type="causal") def add_cooccurrence_edge(self, a_id: str, b_id: str, weight: float = 1.0) -> None: self._graph.add_edge(a_id, b_id, weight=weight, edge_type="cooccurrence") def predecessors(self, node_id: str) -> list[str]: if node_id not in self._graph: return [] return list(self._graph.predecessors(node_id)) def successors(self, node_id: str) -> list[str]: if node_id not in self._graph: return [] return list(self._graph.successors(node_id)) def get_edge_data(self, u: str, v: str) -> Optional[dict]: if not self._graph.has_edge(u, v): return None return dict(self._graph[u][v]) def remove_node(self, node_id: str) -> None: if node_id in self._graph: self._graph.remove_node(node_id) self._id_to_node.pop(node_id, None) # ------------------------------------------------------------------ # Merge # ------------------------------------------------------------------ def _merge_edge(self, u: str, v: str, edge_data: dict) -> None: """Add an edge from u to v, or upgrade the existing one, without ever silently discarding a higher-priority edge type (e.g. a `causal` edge losing to a pre-existing `cooccurrence` edge). """ if not self._graph.has_edge(u, v): self._graph.add_edge(u, v, **edge_data) return existing = self._graph[u][v] incoming_type = edge_data.get("edge_type") existing_type = existing.get("edge_type") incoming_priority = _EDGE_TYPE_PRIORITY.get(incoming_type, -1) existing_priority = _EDGE_TYPE_PRIORITY.get(existing_type, -1) if incoming_priority > existing_priority: # e.g. incoming causal edge beats an existing cooccurrence edge. self._graph.add_edge(u, v, **edge_data) MERGE_EDGE_UPGRADED_COUNT.inc() elif incoming_priority == existing_priority: # Same edge type on both sides: keep the stronger weight # rather than arbitrarily keeping whichever was seen first. existing["weight"] = max(existing.get("weight", 0.0), edge_data.get("weight", 0.0)) else: # Existing edge already outranks the incoming one; nothing # is added, but this is now an explicit, counted decision # rather than a silent drop. MERGE_EDGE_DROPPED_COUNT.inc() def merge_nodes(self, primary_id: str, secondary_id: str) -> None: """Merge `secondary` into `primary`: re-point secondary's edges at primary (without downgrading any of primary's existing edges), combine strength, and remove secondary from the graph. """ if primary_id == secondary_id: return primary = self.get_node(primary_id) secondary = self.get_node(secondary_id) if primary is None or secondary is None: return # Re-point incoming edges (predecessors -> secondary) at primary. for pred in list(self._graph.predecessors(secondary_id)): if pred == primary_id: continue edge_data = dict(self._graph[pred][secondary_id]) self._merge_edge(pred, primary_id, edge_data) # Re-point outgoing edges (secondary -> successors) at primary. for succ in list(self._graph.successors(secondary_id)): if succ == primary_id: continue edge_data = dict(self._graph[secondary_id][succ]) self._merge_edge(primary_id, succ, edge_data) primary.strength = max(primary.strength, secondary.strength) self.remove_node(secondary_id) # ------------------------------------------------------------------ # Decay / pruning # ------------------------------------------------------------------ def decay_all(self) -> None: decay_rates = self._config["memory_type_decay_rates"] floor = self._config["min_strength_floor"] for node in self._id_to_node.values(): rate = decay_rates.get(node.memory_type, self._config["long_term_decay_rate"]) node.strength = max(floor, node.strength - rate) def prune_eligible(self, node: EpisodicNode) -> bool: eligible = self._config["memory_type_consolidation_eligible"] return eligible.get(node.memory_type, True) 

memoria_machinae/memory/stack.py

""" memory/stack.py The consolidation pass: periodically scans active memories and merges near-duplicate nodes into each other based on cosine similarity between their embeddings. Contains the fix for bug #4. Before the fix, cosine similarity inside the merge-dedup loop was computed as: norm_a = emb_a / (emb_a @ emb_a) ** 0.5 norm_b = emb_b / (emb_b @ emb_b) ** 0.5 sim = norm_a @ norm_b with no epsilon guard on the denominator — unlike every other place in the codebase that computes a cosine norm (e.g. salience.py uses `/ (np.linalg.norm(embedding) + 1e-8)`). Since EpisodicNode already tracks an explicit `embedding_meaningful: bool` flag, all-zero or otherwise degenerate embeddings are an anticipated case in this codebase, not a hypothetical one. A single all-zero embedding reaching this loop produces `(0.0) ** 0.5 == 0.0`, and dividing a numpy array by exactly 0.0 produces `nan`/`inf` values rather than raising — which then silently poisons every subsequent similarity comparison built from that node's normalized vector for the rest of the pass. `nan` comparisons are always False, so affected pairs just silently fail to merge; a stray `inf`, if paired with another `inf` from a second degenerate node, can wrongly compare as a similarity of `nan` or an artifact value that passes the threshold, causing two unrelated nodes to be incorrectly merged. The fix does two things: 1. Adds the same epsilon guard used elsewhere in the codebase (`+ 1e-8` on the denominator), so a degenerate embedding can never produce nan/inf or a crash. A true zero vector normalizes to the zero vector, which has cosine similarity 0.0 against everything — never spuriously matching the merge threshold. 2. Additionally skips any pair where either node's `embedding_meaningful` flag is False, before ever computing a similarity. This isn't just a numerical safety net — comparing an embedding the system has already flagged as not meaningful for near-duplicate merging is semantically wrong regardless of whether it happens to be all-zero, so it shouldn't be a candidate for consolidation at all. """ from __future__ import annotations import numpy as np from ..config import CONFIG from ..memory.graph import MemoryGraph from ..metrics import CONSOLIDATION_MERGE_COUNT, CONSOLIDATION_SKIPPED_NONMEANINGFUL_COUNT # Matches the epsilon used elsewhere in the codebase (e.g. salience.py) # for normalizing embeddings that may be zero or near-zero. _COSINE_EPSILON = 1e-8 def cosine_similarity(emb_a: np.ndarray, emb_b: np.ndarray) -> float: """Cosine similarity between two embeddings, safe against zero or near-zero vectors. Never raises, never returns nan/inf: a zero vector normalizes to the zero vector, which has similarity 0.0 against anything (including another zero vector). """ emb_a = np.asarray(emb_a, dtype=float) emb_b = np.asarray(emb_b, dtype=float) norm_a = emb_a / (np.sqrt(emb_a @ emb_a) + _COSINE_EPSILON) norm_b = emb_b / (np.sqrt(emb_b @ emb_b) + _COSINE_EPSILON) return float(norm_a @ norm_b) class MemoryStack: """Owns the consolidation pass over a MemoryGraph: near-duplicate detection and merging of active memory nodes.""" def __init__(self, graph: MemoryGraph, config: dict | None = None): self.graph = graph self._config = config or CONFIG self._threshold = self._config["dedup_similarity_threshold"] def consolidate(self) -> int: """Scan active nodes (those with an embedding) and merge any pair whose cosine similarity meets the configured threshold. Returns the number of merges performed. """ active = [n for n in self.graph.all_nodes() if n.embedding is not None] merged_ids: set[str] = set() merge_count = 0 for i, node_a in enumerate(active): if node_a.node_id in merged_ids: continue for node_b in active[i + 1:]: if node_b.node_id in merged_ids: continue if not node_a.embedding_meaningful or not node_b.embedding_meaningful: CONSOLIDATION_SKIPPED_NONMEANINGFUL_COUNT.inc() continue sim = cosine_similarity(node_a.embedding, node_b.embedding) if sim >= self._threshold: self.graph.merge_nodes(node_a.node_id, node_b.node_id) merged_ids.add(node_b.node_id) merge_count += 1 CONSOLIDATION_MERGE_COUNT.inc() return merge_count

""" schema/common.py Shared text-parsing helpers for schema and meta-schema nodes, used by both schema/precondition.py and schema/inducer.py. """ schema/precondition.py Learns which entities tend to precede a schema's action along causal edges, i.e. its likely preconditions. Contains the fix for bug #1. Before the fix, the schema's own action entity was excluded from its precondition list with: entity.lower() not in schema_node.text.lower().split(':')[1].split(':')[0] Two separate problems here: 1. `in` on strings is *substring* containment, not equality. The parsing assumed a fixed "schema:{action}:{outcome}" text layout. It breaks the moment `pattern_key` is a bigram like "grasp->pick:FAILED" (schema text "schema:grasp->pick:FAILED"), because splitting on ':' alone leaves "grasp->pick" un-split, so bigram schemas never correctly identified either action. memoria_machinae/schema/inducer.py

""" schema/inducer.py Composes flat (level-1) schemas into higher-level meta-schemas by grouping schema/meta-schema nodes that share the same underlying action(s) and rolling groups above a minimum size into a new `meta_schema_L{level}` node. Contains the fix for bug #2. Before the fix, the grouping key used to decide which nodes belong together at a given hierarchy level was extracted with: parts = node.text.split(':') action_token = parts[1].split('->')[0].strip() This works for level-1 schema text ("schema:grasp:FAILED | ...") since parts[1] == "grasp" cleanly. But it breaks the moment `node` is itself a meta-schema node produced by a *previous* composition pass, e.g. "meta_schema_L2:grasp | composed_of 2 schemas". Splitting on ':' there gives parts[1] == "grasp | composed_of 2 schemas" (the entire tail, including the trailing description, because there's no second ':' to stop at), and .split('->')[0] does nothing to help since there's no '->' in that string either. The resulting "action_token" for every level-2+ meta-schema node therefore includes its own unique "composed_of N schemas" suffix, so no two meta-schema nodes ever produce the same grouping key — which means groups above the minimum size never form, and hierarchical composition silently stops working above level 2, no matter how `schema_hierarchy_levels` is configured. The fix reuses the same robust parser as the bug #1 fix (schema/common.py's extract_schema_actions), which strips the trailing " | ..." description *before* parsing the action segment. That parser already worked correctly for both flat and meta-schema node text at any level — it just wasn't being reused here, which is exactly the kind of duplicated, drifted logic that caused the two bugs in the first place. Sorting means two bigram schemas that record the same pair of actions in different orders still group together. Returns None for text that doesn't parse into any action tokens at all. Notes on scope

service/auth.py is newly written for this fix, since only the single buggy if statement was quoted in the original review, not the surrounding module (which in the real codebase presumably wraps this in a FastAPI HTTPException). I used a lightweight AccessDenied exception carrying a status_code attribute instead of depending on FastAPI directly, so the fix is testable in isolation; at the real API boundary this should be caught and translated into an actual HTTPException(status_code=exc.status_code, detail=str(exc)) (or your framework's equivalent) — that translation layer isn't part of this fix.

Logging + metric on bypass use is a small scope addition beyond the literal "add a flag" fix, included because a bypass that fires silently — even when legitimately enabled — is much harder to audit or notice if it's ever misused or left on by accident. Straightforward to drop if you'd rather keep the diff to just the flag gate.

validate_config() requiring dev_mode to be explicitly present is likewise a small addition in the same spirit as "fail closed by default" — happy to relax it back to a plain default if you'd rather not enforce explicitness at the config-validation layer.

This wraps up all five items from the original code review (#3 causal-edge merge, #1 precondition substring bug, #2 hierarchical composition, #4 zero-embedding NaN, #5 auth bypass). The two performance items flagged earlier (#8 O(n²) dedup at scale, #9 cross-encoder in the dream-replay loop) are still open if useful to pick up next, though those are optimization work rather than correctness/security bugs.
